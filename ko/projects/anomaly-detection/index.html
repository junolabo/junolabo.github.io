Project 1-2

VLM Anomaly Detection

fine-tuning한 VLM이 camera image와 로봇·장비 상태로 12종 이상의 이상 상황을 분류합니다. 로봇이 복구할 수 있으면 로봇이 복구하고, 할 수 없으면 사람을 부릅니다.

역할
단독 개발
기간
Project 1의 일부 (2023.10 - 현재)
상태
직영 매장에서 운영
문제구조동작설계 판단한 건을 끝까지 따라가기범위연결된 프로젝트

문제

매장에서 무엇이 잘못됐는지 확인하는 일은 사람이 필요했습니다. 매장에 나가는 관리자나 원격으로 지켜보는 운영 인력이 맡았습니다. 이들 없이 운영하려면, 시스템이 상황을 알아차리고 무엇을 할지까지 정해야 합니다.

  1. 이상 상황은 모양이 정해져 있지 않습니다.컵 쓰러짐, 오염, 장비 고장 등 종류가 많습니다. 종류마다 규칙이나 검출기를 따로 만드는 방식으로는 새로 나타나는 종류를 따라가지 못합니다.
  2. 영상만으로는 부족합니다.영상에는 그 순간 로봇과 장비가 무엇을 하고 있는지가 나오지 않습니다. 상태를 영상과 함께 읽어야 합니다.
  3. 틀린 분류가 로봇 동작이 되면 안 됩니다.모델은 틀릴 수 있고, 출력의 형식이 깨질 수도 있습니다. 모델과 로봇 사이에 검사하는 단계가 있어야 합니다.
  4. 매장은 이미 운영 중이었습니다.운영 중인 시스템의 인터페이스를 바꾸지 않고 새 기능을 붙여야 했습니다.

구조

동작

VLM anomaly detection

운영

camera image와 로봇·장비 상태를 2초마다 묶어 VLM에 넣습니다. VLM은 매장 상황으로 QLoRA fine-tuning한 소형 모델이고, 컵 쓰러짐, 오염, 고장 등 12종 이상의 상황을 분류합니다.

모델의 출력은 고정된 schema로 강제하므로 항상 해석할 수 있습니다. 결과를 쓰기 전에 code로 쓴 규칙이 검사합니다. 입력이 최신이었는지, 입력을 준 node가 정상이었는지, 손 진입이나 쏟아짐 같은 규칙과 결과가 맞는지를 봅니다.

이전 방식: 영상 이상 감지 모델이 음료 유출과 심한 오염을 찾아 그 칸의 서빙을 막았습니다. 비정형 상황에는 VLM이 더 알맞아서 VLM으로 바꿨습니다.

상황별 대응

원칙: 로봇이 풀 수 있는 것은 로봇이 풉니다. 사람이 필요한 것은 알림을 보냅니다.

상황대응누가 하는가
컵이 쓰러짐. 음료는 흐르지 않음컵을 집어 폐기로봇
컵이 쓰러지고 음료가 흐름관리자 호출사람
건물 안의 오염Orchestrator Agent가 청소 로봇을 보냄청소 로봇
치명적인 장비 고장알림 전송사람

검토한 사례로 모델 개선

사람이 검토한 결과가 모델과 달랐던 사례는 다음 학습 데이터로 들어갑니다. VLM은 MLOps pipeline으로 갱신하는 세 모델 중 하나입니다.

설계 판단

판단이유막는 문제
영상을 로봇·장비 상태와 묶음영상에는 로봇이 하는 일이 나오지 않음영상만으로 상황을 판단하는 것
출력이 고정된 schema를 따르게 함자유로운 글로는 동작을 고를 수 없음해석할 수 없는 출력
VLM과 동작 사이에 규칙 검사를 둠모델은 틀릴 수 있음틀린 결과가 로봇 동작이 되는 것
운영 중인 시스템 옆에 읽기 전용 사이드카로 붙임매장이 이미 운영 중이었음운영 중인 ROS 2 인터페이스를 바꾸는 것
VLM은 인식만 함. 로봇의 동작을 고르거나 제어하지 않음상황 종류별 대응은 모델 밖에서 정해 둠모델의 출력이 로봇을 직접 움직이는 것

판단

관측camera image와 로봇·장비 상태를 묶음. 2초마다 반복
분류VLM이 상황의 종류를 고정된 schema로 반환
검사입력이 최신이었는지, 결과가 규칙과 맞는지를 규칙 검사가 확인
대응음료가 흐르지 않았으면 로봇이 컵을 집어 폐기. 흘렀으면 관리자 호출

지금은 정해 둔 flow가 대응을 실행합니다. Task Planning Agent가 대응 순서(폐기, 재제조, 청소)를 판단하는 방식은 실로봇 테스트 단계입니다.
